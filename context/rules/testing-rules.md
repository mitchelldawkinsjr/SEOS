## Testing rules

- Run the project build command before finishing implementation.
- Run the project test command when behavior or UI changes (skip only if the repo has no test suite).
- Prefer extending existing tests over inventing a new test harness.
- Acceptance criteria should be checkable from the PR (tests, screenshots, or both).
- UI changes require screenshots committed under `artifacts/issue-{N}/` and linked in the issue completion comment.
